# Jewish Chronology Lab / Лаборатория еврейской хронологии

Отдельное статическое исследовательское приложение по [jewTeX #23](https://github.com/Ishayahu/jewTeX/issues/23).

**Демо после включения GitHub Pages:** https://ishayahu.github.io/jewish-chrono/

## Возможности
- Выбор конкурирующих датировок и собственных годов АМ.
- Независимые гипотезы-связи между событиями; возраст 47 лет — отдельное включаемое свидетельство.
- Строгий режим отклоняет несовместимые варианты; исследовательский режим показывает величину конфликта и происхождение расчёта.
- Временная шкала, таблица событий и ссылки на канонические XML-источники в `Ishayahu/jewTeX_TEXTS_DB`.
- Публичный каталог свидетельств и правил в `data/*.json`; личные сценарии — в localStorage, с экспортом/импортом JSON.

## Запуск локально
Нужен обычный статический HTTP-сервер (нельзя запускать напрямую через `file://`, потому что данные подгружаются через `fetch`):

```sh
python3 -m http.server 8000
# http://localhost:8000/
node --test tests/*.test.mjs
```

Зависимостей, серверного приложения и секретов нет.

## GitHub Pages
Перейдите в **Settings → Pages → Build and deployment → Source: GitHub Actions**. Коммит в ветку `main` запускает `.github/workflows/pages.yml` и публикует корень репозитория. До завершения Actions адрес сайта может возвращать 404.

## Методологические границы
Согласованность чисел **не доказывает** достоверность датировки или отождествления исторических лиц. Сообщение источника, гипотеза исследователя и арифметически производная дата различаются по типу и статусу. Конкретные годы 3927/3948 — вычисленные иллюстрации, не даты, приписанные «Цемах Давид». Сведения с пометкой о необходимости проверки не выдаются за проверенные. Модель оперирует целыми годами АМ (в том числе тестовыми отрицательными значениями); точные дни рождения и конвертация календарей не реализованы.

Исходная задача и обсуждение источников: [jewTeX #23](https://github.com/Ishayahu/jewTeX/issues/23).


## Автоматическая синхронизация из XML

Единственный канонический источник публичных данных — машинные узлы `<chronology_data version="1" calendar="AM">…</chronology_data>` внутри XML-файлов каталога
[`jewTeX_TEXTS_DB/lastov_ishayahu/chronos/`](https://github.com/Ishayahu/jewTeX_TEXTS_DB/tree/master/lastov_ishayahu/chronos).
Видимая проза и машиночитаемая часть существуют рядом; согласование пока **ручное**. Три XSLT-преобразования `.meta/html.xslt`, `.meta/quote_html.xslt` и `.meta/markdown.xslt` явно исключают этот узел из вывода.

Скрипт [`scripts/sync_chronology.py`](scripts/sync_chronology.py) обходит **все XML-файлы верхнего уровня каталога**, кроме `info.xml`, находит все `chronology_data`, проверяет идентификаторы, ссылки и корректность диапазонов, затем детерминированно генерирует `data/{events,claims,constraints}.json`. Автоматизация через `.github/workflows/pages.yml`:

1. На каждый push в `main`, по ручному запуску или по расписанию (каждые три часа) получают код лаборатории и актуальный `master` базы текстов.
2. Генератор обрабатывает XML, выполняются Python unit tests, Node tests и проверка синтаксиса JavaScript.
3. Если JSON изменился, GitHub Actions автоматически коммитит новые JSON-файлы в `main`. Исходные XML при этом не изменяются.
4. Тот же workflow развёртывает актуальный JSON и интерфейс на GitHub Pages. Дополнительный сервер или персональный токен для чтения публичного репозитория не нужен.

При ошибке структуры XML генератор **останавливается**, не заменяя JSON неполным файлом. Генератор никогда не анализирует прозу и не выдаёт вывод ИИ за исходное свидетельство. Новые датированные события вне текущих двух переключаемых параметров отображаются как дополнительные строки каталога; для новых интерактивных зависимостей потребуется расширение solver/UI.

**Проверить локально** (нужна соседняя локальная копия базы текстов):

```sh
python3 scripts/sync_chronology.py --source-dir ../jewTeX_TEXTS_DB/lastov_ishayahu/chronos --output-dir data
python3 scripts/sync_chronology.py --source-dir ../jewTeX_TEXTS_DB/lastov_ishayahu/chronos --output-dir data --check
python3 -m unittest discover -s tests -p 'test_*.py'
node --test tests/*.test.mjs
```
